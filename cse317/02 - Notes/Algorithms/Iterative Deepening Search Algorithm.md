## Starting Point and the Problem

We face a classic engineering dilemma in search:
- **Breadth-First Search (BFS):** Complete and optimal (for uniform step costs), but unusable on large problems due to exponential memory ($O(b^d)$).
- **Depth-First Search (DFS):** Highly memory-efficient ($O(bd)$ linear memory), but neither complete nor optimal.
- **Depth-Limited Search (DLS):** Solves the infinite loop problem of DFS, but requires knowing the goal depth $d$ in advance. If limit $l < d$, it fails; if $l > d$, it is non-optimal.

We need a search algorithm that combines the **completeness and optimality of BFS** with the **linear space efficiency of DFS**. That algorithm is **Iterative Deepening Search (IDS)**.

---

## Developing the Idea

If we do not know the correct depth limit $l$, the rational strategy is to try all possible limits systematically:
- Run Depth-Limited Search with limit $l = 0$.
- If no goal is found, run Depth-Limited Search with limit $l = 1$.
- If no goal is found, run Depth-Limited Search with limit $l = 2$.
- Continue increasing $l$ until a goal is found or DLS returns failure without cutoffs.

```
Limit = 0:  [ Root ]
Limit = 1:  [ Root ] ──► [ Level 1 Nodes ]
Limit = 2:  [ Root ] ──► [ Level 1 Nodes ] ──► [ Level 2 Nodes ]
Limit = 3:  [ Root ] ──► [ Level 1 Nodes ] ──► [ Level 2 Nodes ] ──► [ Goal Found! ]
```

At first glance, this appears terribly wasteful because states near the root are regenerated multiple times. However, mathematical analysis reveals that this regeneration overhead is negligible!

---

## Algorithm Specification

```python
def ITERATIVE_DEEPENING_SEARCH(problem):
    depth = 0
    while True:
        result = DEPTH_LIMITED_SEARCH(problem, depth)
        if result != 'cutoff':
            return result  # Returns Solution or Failure
        depth += 1
```

## Mathematical Analysis of Regeneration Overhead

Why is Iterative Deepening not horribly slow?
In an exponential search tree, the vast majority of nodes are at the bottom level.
Let $b$ be the branching factor and $d$ be the depth of the shallowest goal:
- Nodes at depth $d$ are generated **$1$ time**.
- Nodes at depth $d-1$ are generated **$2$ times**.
- Nodes at depth $d-2$ are generated **$3$ times**.
- Nodes at depth $1$ are generated **$d$ times**.

The total number of node generations across all iterations is:
$$N(\text{IDS}) = (d)b^1 + (d-1)b^2 + (d-2)b^3 + \dots + 1 \cdot b^d$$

Compare this with Breadth-First Search, which generates:
$$N(\text{BFS}) = 1 + b^1 + b^2 + \dots + b^d$$

### Concrete Numerical Comparison ($b = 10, d = 5$)

- **BFS Node Generations:**
  $$N(\text{BFS}) = 1 + 10 + 100 + 1,000 + 10,000 + 100,000 = 111,111$$

- **IDS Node Generations:**
  $$N(\text{IDS}) = 5(10) + 4(100) + 3(1,000) + 2(10,000) + 1(100,000) = 50 + 400 + 3,000 + 20,000 + 100,000 = 123,450$$

Notice that IDS generates only $\approx 11\%$ more nodes than BFS!

### Asymptotic Ratio
Mathematically, the ratio of IDS to BFS as $d \to \infty$ is:
$$\frac{N(\text{IDS})}{N(\text{BFS})} \approx \frac{b}{b - 1}$$
- For $b = 10$, overhead is only $\frac{10}{9} \approx 1.11$ ($11\%$).
- For $b = 4$, overhead is $\frac{4}{3} \approx 1.33$ ($33\%$).
- For $b = 2$, overhead is $\frac{2}{1} = 2.0$ ($100\%$, at most a factor of 2).

In return for this small time factor, IDS reduces memory consumption from **gigabytes/terabytes ($O(b^d)$) down to kilobytes ($O(bd)$)**.

---

## Evaluation Properties

- **Completeness:** Complete (if branching factor $b$ is finite).
- **Optimality:** Optimal whenever step costs are equal (uniform), exactly like BFS.
- **Time Complexity:** $O(b^d)$.
- **Space Complexity:** $O(bd)$ (Strictly linear memory!).

---

## Summary Verdict

Iterative Deepening Search is universally preferred over BFS for large, uninformed search spaces where step costs are uniform and memory is constrained.
