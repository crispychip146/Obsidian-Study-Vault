# Heuristic Functions and Properties

> 📖 **Reading Order:** Step 16 of 43 | **Module 4:** Informed (Heuristic) Search & A* Search  
> ◄ **Previous:** [[8-Puzzle and Vacuum World State Space Example]] | ► **Next:** [[Greedy Best-First Search Algorithm]]

## Starting Point and the Problem

Uninformed search algorithms (BFS, UCS, DFS) explore blindly, with no intuition regarding which unexpanded branch lies physically or conceptually closer to the goal. Consequently, they expand massive numbers of irrelevant states. If an agent had domain-specific knowledge—an estimate of the remaining cost from any state to the goal—it could prioritize exploring promising directions. This domain knowledge is formalized as a **Heuristic Function** $h(n)$.

---

## Developing the Idea

Consider navigating a road network. While the actual road path involves winding curves and speed limits, the straight-line Euclidean distance ("as the crow flies") to the destination provides an immediate, computationally cheap estimate.

```
                  [ Node n ]
                     │  \
              g(n)   │   \  h*(n): True optimal remaining cost
         (Cost so far)│    \  h(n):  Heuristic estimate
                     ▼     ▼
                [ Start ] ──► ──► [ Goal State ]
```

- $g(n)$: The exact cost incurred so far from the initial state to node $n$.
- $h(n)$: The estimated cost of the cheapest path from the state at node $n$ to a goal state.
- $h^*(n)$: The *true*, optimal path cost from node $n$ to the goal.

By definition, if $n$ is already a goal state, its remaining cost is zero:
$$h(\text{Goal}) = 0$$

---

## Key Mathematical Properties of Heuristics

### 1. Admissibility (Never Overestimating)

A heuristic function $h(n)$ is **admissible** if it never overestimates the true cost to reach the goal:
$$h(n) \le h^*(n) \quad \forall n$$

- **Intuition:** An admissible heuristic is optimistic. Because it thinks the cost is less than or equal to reality, the search will never prematurely discard a good path thinking it is too expensive.
- **Role:** Admissibility is the necessary and sufficient condition for **A* Tree Search** to guarantee an optimal solution.

---

### 2. Consistency (Monotonicity)

A heuristic function $h(n)$ is **consistent** (or *monotonic*) if, for every node $n$ and every successor $n'$ generated by an action $a$, the estimated cost of reaching the goal from $n$ is no greater than the step cost $c(n, a, n')$ plus the estimated cost from $n'$:
$$h(n) \le c(n, a, n') + h(n')$$

```
                         n
                        / \
          c(n, a, n')  /   \  h(n)
                      ▼     \
                     n' ────► Goal
                       h(n')
```

- **Intuition:** This is the **triangle inequality** applied to the heuristic. It guarantees that the estimated remaining cost cannot drop by more than the actual step cost incurred.
- **Consequence for $f$-cost:** If $h$ is consistent, the total evaluation function $f(n) = g(n) + h(n)$ is **monotonically non-decreasing along any path**:
  $$f(n') = g(n') + h(n') = g(n) + c(n, a, n') + h(n') \ge g(n) + h(n) = f(n)$$
- **Role:** Consistency is the condition required for **A* Graph Search** to guarantee optimality without needing to re-open nodes in the explored set.

---

### Theorem: Consistency Implies Admissibility

**Theorem:** Every consistent heuristic is admissible.

*Proof by Induction on Path Length to Goal:*
1. Let $n = n_0, n_1, n_2, \dots, n_k = \text{Goal}$ be the true optimal path from $n$ to the goal, where $h^*(n) = \sum_{i=0}^{k-1} c(n_i, a_i, n_{i+1})$.
2. By consistency:
   $$h(n_0) \le c(n_0, a_0, n_1) + h(n_1)$$
   $$h(n_1) \le c(n_1, a_1, n_2) + h(n_2)$$
   $$\vdots$$
   $$h(n_{k-1}) \le c(n_{k-1}, a_{k-1}, n_k) + h(n_k)$$
3. Summing these inequalities telescopically:
   $$h(n_0) \le \sum_{i=0}^{k-1} c(n_i, a_i, n_{i+1}) + h(n_k)$$
4. Since $n_k$ is the Goal, $h(n_k) = 0$.
5. The sum of step costs is precisely the optimal cost $h^*(n)$:
   $$h(n_0) \le h^*(n_0)$$
6. Therefore, $h(n)$ is admissible. $\blacksquare$

*(Note: The reverse is not always true; an admissible heuristic can occasionally be inconsistent in general graphs, though in most practical problems admissible heuristics are also consistent).*

---

### 3. Heuristic Dominance

Given two admissible heuristics $h_1(n)$ and $h_2(n)$, we say that **$h_2$ dominates $h_1$** if:
$$h_2(n) \ge h_1(n) \quad \forall n$$

- **Consequence:** Dominance means $h_2$ is closer to the true cost $h^*$ than $h_1$.
- **Theorem:** If $h_2$ dominates $h_1$, A* using $h_2$ will expand a subset of the nodes expanded by A* using $h_1$ (it will never expand more nodes than $h_1$).
- A higher admissible value provides better pruning power!

---

## Generating Admissible Heuristics

How do we design admissible heuristics systematically?

### 1. Relaxed Problems
A problem with fewer restrictions on the actions is called a **relaxed problem**. The cost of an optimal solution to a relaxed problem is an admissible heuristic for the original problem!

*Example (8-Puzzle):*
- *Original Rule:* A tile can move from square A to square B if A is adjacent to B AND B is blank.
- *Relaxation 1 (Ignore Blank):* A tile can move from A to B if A is adjacent to B.
  $\implies$ Yields the **Manhattan Distance Heuristic** ($h_2$): sum of horizontal and vertical distances of tiles from their goal positions.
- *Relaxation 2 (Ignore Adjacency and Blank):* A tile can move from A to B anywhere.
  $\implies$ Yields the **Misplaced Tiles Heuristic** ($h_1$): number of tiles in wrong positions.

Since Manhattan distance accounts for movement steps while misplaced tiles counts only mismatch, $h_{\text{Manhattan}}(n) \ge h_{\text{Misplaced}}(n)$ for all states. Thus, **Manhattan distance dominates misplaced tiles**.

### 2. Combining Heuristics
If we have $m$ different admissible heuristics $h_1, h_2, \dots, h_m$ and none dominates all others, we can construct a composite heuristic:
$$h_{\text{composite}}(n) = \max\{h_1(n), h_2(n), \dots, h_m(n)\}$$
$h_{\text{composite}}$ is guaranteed to be admissible, consistent (if components are consistent), and dominates every individual heuristic!

---

## Common Mistakes

- Using a heuristic that overestimates even for a single state (destroys the optimality guarantee of A*).
- Believing an admissible heuristic guarantees graph-search optimality without consistency (in graph search, inconsistency can require expensive re-opening of closed nodes).
