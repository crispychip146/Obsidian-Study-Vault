# Uninformed Search Strategies

> 📖 **Reading Order:** Step 09 of 43 | **Module 3:** Problem Solving & Uninformed Search  
> ◄ **Previous:** [[Problem-Solving Agents and State Space Formulation]] | ► **Next:** [[Breadth-First Search Algorithm]]

## Starting Point and the Problem

When an agent searches a state space, it needs a strategy to determine the order in which nodes on the frontier are expanded. In many domains, the agent has no information about the number of steps or the path cost from the current state to the goal; it only knows how to generate successors and test whether a state is a goal. Such techniques are called **Uninformed Search Strategies** (or *Blind Search*). The central problem is evaluating and comparing these strategies across formal criteria.

---

## Developing the Idea

Uninformed search algorithms differ solely in the order in which nodes are expanded from the **frontier**.
- If we expand the shallowest nodes first: **Breadth-First Search (BFS)**.
- If we expand the lowest-cost path first: **Uniform-Cost Search (UCS)**.
- If we expand the deepest nodes first: **Depth-First Search (DFS)**.
- If we systematically limit depth: **Depth-Limited Search (DLS)** and **Iterative Deepening Search (IDS)**.
- If we search simultaneously from both ends: **Bidirectional Search**.

---

## The Four Evaluation Criteria

Search algorithms are rigorously judged according to four mathematical criteria:

1. **Completeness:** Is the algorithm guaranteed to find a solution when at least one solution exists, or correctly report failure if no solution exists?
2. **Optimality:** Does the strategy find the optimal solution—the solution with the lowest path cost $g(n)$—among all possible solutions?
3. **Time Complexity:** How many nodes are generated or how long does it take to find a solution?
4. **Space Complexity:** How much memory (maximum number of nodes stored simultaneously in memory) is required to perform the search?

### Complexity Parameters
- $b$: **Branching factor** (the maximum number of successors generated by any state).
- $d$: **Depth of the shallowest goal node**.
- $m$: **Maximum depth of the state space** (can be $\infty$ if infinite paths exist).
- $C^*$: Cost of the optimal solution.
- $\epsilon$: A strictly positive lower bound on every step cost ($c(s,a,s') \ge \epsilon > 0$).

---

## Comprehensive Comparison Matrix

The table below summarizes the performance of uninformed search strategies (assuming graph search, or tree search where noted):

| Algorithm | Complete? | Optimal? | Time Complexity | Space Complexity | Frontier Implementation |
|---|---|---|---|---|---|
| **Breadth-First Search (BFS)** | Yes (if $b$ is finite) | Yes (if step costs are uniform) | $O(b^d)$ | $O(b^d)$ | FIFO Queue |
| **Uniform-Cost Search (UCS)** | Yes (if step costs $\ge \epsilon > 0$) | Yes (always optimal) | $O\left(b^{1 + \lfloor C^* / \epsilon \rfloor}\right)$ | $O\left(b^{1 + \lfloor C^* / \epsilon \rfloor}\right)$ | Priority Queue ordered by $g(n)$ |
| **Depth-First Search (DFS)** | No (fails on $\infty$ paths in Tree Search); Yes (in finite state Graph Search) | No | $O(b^m)$ | $O(bm)$ | LIFO Queue (Stack) |
| **Depth-Limited Search (DLS)** | Yes if $l \ge d$; No if $l < d$ | No | $O(b^l)$ | $O(bl)$ | LIFO Queue with depth limit $l$ |
| **Iterative Deepening (IDS)** | Yes (if $b$ is finite) | Yes (if step costs are uniform) | $O(b^d)$ | $O(bd)$ | LIFO Queue run iteratively |
| **Bidirectional Search** | Yes (if $b$ finite & BFS both ends) | Yes (if step costs uniform) | $O(b^{d/2})$ | $O(b^{d/2})$ | Two FIFO Queues |

## Technical Details

### The Fundamental Space Dilemma

Why does BFS fail on large real-world problems despite being complete and optimal for uniform costs?
Consider $b = 10$, generating 100,000 nodes/second, with 1,000 bytes per node:

| Depth $d$ | Nodes Generated | Time Required | Memory Required |
|---|---|---|---|
| **2** | $110$ | $1.1\text{ ms}$ | $110\text{ KB}$ |
| **4** | $11,110$ | $0.11\text{ s}$ | $11\text{ MB}$ |
| **6** | $10^6$ | $11\text{ s}$ | $1\text{ GB}$ |
| **8** | $10^8$ | $19\text{ minutes}$ | $103\text{ GB}$ |
| **12** | $10^{12}$ | $3.5\text{ years}$ | $1\text{ Petabyte}$ |
| **14** | $10^{14}$ | $350\text{ years}$ | $100\text{ Exabytes}$ |

Memory, not time, is the true bottleneck of breadth-first search. While an algorithm can run for days, memory exhausts in minutes. This directly motivates **Depth-First Search** and **Iterative Deepening Search**, which require only $O(bd)$ linear memory.

---

## Common Mistakes

- Believing BFS is optimal for arbitrary non-uniform step costs (e.g., if a 1-step path costs 100 and a 2-step path costs $1+1=2$, BFS will mistakenly return the 1-step path of cost 100).
- Assuming Iterative Deepening is inefficient because it regenerates nodes. In reality, the exponential growth of trees means the bottom level dominates ($b^d$), and the regeneration overhead is negligible ($\approx \frac{b}{b-1}$).
